## What changed

- **MMSP server** (`mmsp.integration.server`, `@prismshadow/mmsp/integration/server`): serves the models of a table over HTTP as MMSP streams. A row is `model_id`, `api_key` and `server_model_id` (the id clients name), required, and `base_url`, `client_type`, which empty or absent leave to `AutoLLMClient` (its default endpoint; `CLIENT_TYPE`, else the official client the model id names). `api_keys` lists the bearer keys clients may send; several are allowed; an empty list is an open server, said at start. Both come from one JSON file, `--config PATH` or `MMSP_SERVER_CONFIG`, read by `load_server_config` / `loadServerConfig`, where a `base_url`, `api_key`, `client_type` or `api_keys` cell starting with `$` is read from the environment and an unset variable stops the start. `create_server_app(models, api_keys)` / `createServerApp({ models, apiKeys })` take the rows and return the Flask / Express app; `start_server` / `startServer` (which returns the `http.Server`) start it; `--host`, `--port` default to `127.0.0.1:25752`, so a client's base URL is `http://127.0.0.1:25752/v1`. Every row's upstream client is built once at start; an empty table, a missing required column, a duplicate `server_model_id`, an empty key or a row its client refuses stops the start with the row or key named.
- `GET /v1/models` lists the table in OpenAI's shape: `{"object": "list", "data": [{"id": <server_model_id>, "object": "model", "created": <unix s>, "owned_by": "mmsp"}, ...]}`.
- `POST /v1/stream` takes `{"model", "messages", "config"}` and answers with server-sent events: one `data: <UniEvent JSON>` per event of the public stream, then `data: [DONE]`, with a `: keep-alive` comment every 15 s while the model is silent. `config` is forwarded whole, so a `trace_id` is saved on the server too. A disconnect aborts the upstream request. Body limit 50 MB.
- Errors are `{"error": {"type", "message", ...}}`: 401 `AuthenticationError` without one of the server's keys, 400 `InvalidRequestError` for a malformed body, 404 `NotFoundError` for a model not in the table and for any other route, 413 for a body over the limit; once a stream has begun, one error event, then `data: [DONE]`.
- Bytes travel as base64; only the `data` of `inline_data.*` and `inline_thinking.*` items is decoded back.
- **`mmsp` client** (`mmsp/`, `MmspClient`), compatible client type `mmsp`: yields the server's public stream as sent, bytes decoded, and saves no trace of its own (the server saves it). Reads `MMSP_API_KEY` / `MMSP_BASE_URL` under the credential rule, default `http://127.0.0.1:25752/v1`; requests `{base_url}/stream` and `{base_url}/models`. `list_models` returns the table's ids.
- Every error the server reports, a refusal or an error event, is raised by the `mmsp` client as the new `UpstreamError` (`client`, `status`, `error_type` / `errorType`, `message`, and `error`, the server's error object with its fields), exported from both packages.
- `mmsp.wire` / `src_ts/src/wire.ts`: the routes, the defaults and the byte codec the server and the client share, and the error encoding the server writes.
- `resolve_server_config(config, source)` / `resolveServerConfig(config, source)`: the shape check and `$VAR` resolution of `load_server_config`, shared with the playground. `read_server_config(path)` / `readServerConfig(path)`: the file as written, `$VAR` cells unresolved and every key kept.
- `announce_server` / `announceServer`: the start lines `Starting MMSP server at <base URL>`, `Serving models: <ids>` and, for an open server, `Open server: api_keys is empty, every request is accepted`; `start_server` / `startServer` and the playground print them.
- `GET /v1/metrics` (`ServerMetrics`, under the key rule of `/v1/`): since start, in total and per model, requests, successes (ended with the stop event), failures (ended in an error), disconnects (counted apart), in flight, success rate, p50/p90 of the first-event and total latency over the latest 1000 successes, tokens, `tokens_out` (thinking + response), `generation_ms` (first event to end, summed) and `tps` (`tokens_out` per second of `generation_ms`); refusals before a model and `errors` (the latest 20 failures, newest first) in total; each model's last request time, outcome and error. `?window=N` (10 to 7200) adds `window`: the last N seconds in 10 s buckets of the clock, rounded up to whole buckets and kept for 2 h, a request counted in the bucket it began in and a bucket's percentiles over its first 64 successes; sums and per-bucket columns in total and per model, and `previous`, the sums of the window before; any other value is a 400 `InvalidRequestError`. The playground's server page draws them; the 404 message lists the three routes.
- Playground: `mmsp` ("MMSP server") in the client-type picker, default base URL `MMSP_BASE_URL` or `http://127.0.0.1:25752/v1`; a server page at `/server/` (linked from the top bar) where a models table (Client type Auto and Base URL Default when left empty), `api_keys`, host and port are saved to `MMSP_SERVER_CONFIG`, else `server.json` in the cache directory (the CLI's format plus `host` and `port`, cells as typed), and the server is started from the saved file in the playground process (`GET`, `PUT /server/api/config`; `GET /server/api/status`, with the running `config`; `GET /server/api/metrics`, the running server's metrics read in-process, with `?window=N` as on `/v1/metrics`, `{"running": false}` when none runs; `POST /server/api/start`, `/restart`, `/stop`; a `$VAR` cell is read from the playground's environment at start). The page has a header with the state and the base URL, and three tabs: Overview, Models (a model row collapses to one line, served id, upstream and state, and opens to edit) and Settings (keys, host, port, the file's path). Each row, key and the listen pair reads Live, Saved or Unsaved; Save, also Ctrl/Cmd+S, writes the file; Start is enabled once a file is saved; Apply (`/restart`) builds the new server before stopping the old one. Overview shows a checklist (add a model, save, start) while the server is stopped; while it runs, refreshed every 3 s over a range of 5 min, 15 min or 1 h: six tiles (Requests, Success, Latency p50, Latency p90, Tokens out, TPS) with their change against the previous range, a card per model (state, requests, success, p50, p90, TPS, last outcome, trend) that opens its row on Models, the Requests chart by outcome, the Latency chart with p50 and p90, and the Errors list. An unsaved draft stays in the browser under `mmsp.playground.server`; starts and stops print to the playground's console, and at start the playground prints the tracer and server page links.
- Playground chat page: a listed model is an entry of model id, client type, API key and base URL; entries sharing a model id are listed apart, described `<client type> · <host>`, and picking one fills in all four.
- Docs: an MMSP Server section in the README, a Server page under Tools on the site, with a Metrics section, `mmsp` in the client lists, a section on errors through a server, and the skills references.
