# RFC 重新表述为十项以名词为题的规范

- **Date:** 2026-10-24
- **Type:** process
- **Scope:** `design`, `site`, `skills`, `docs`
- **PR:** [#298](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/298), [#N](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/N)

[English](2026-10-24-rfc-specifications.md)

## 变更内容

- RFC 改为十篇以名词为题的文档，与 IETF RFC 的做法相同，顺序按项目负责人给出的中文标题排列，这些标题就是各篇中文版的 H1：MMSP-RFC-0001 RFC 流程（The RFC Process），MMSP-RFC-0002 消息协议（Message Protocol），MMSP-RFC-0003 消息请求（Message Requests），MMSP-RFC-0004 消息保真（Message Fidelity），MMSP-RFC-0005 客户端路由（Client Routing），MMSP-RFC-0006 服务上游密钥（Upstream Credentials），MMSP-RFC-0007 异常类型（Error Types），MMSP-RFC-0008 请求中断（Request Interruption），MMSP-RFC-0009 协议转换（Protocol Conversion），MMSP-RFC-0010 轨迹记录（Trace Recording）。
- 每篇 RFC 都改用 `design/0000-template.md` 的形式：先是 Abstract，然后是编号的各节，从 Introduction、Conventions and Terminology 到正文各节，规范类 RFC 最后一节是由 Enforced by 改名而来的 Conformance。规范性语句使用 BCP 14 关键词 MUST、MUST NOT、SHOULD、SHOULD NOT 与 MAY，中文版写作必须、不得、应当、不应与可以。类别 `rule` 改为 `spec`，`[summary]: #summary` 锚点行随之删除。
- 0.5.5 的 RFC 与 #298 的十二篇按主题归并：同一套协议、两个包与精简的消息并入 MMSP-RFC-0002；流语法、stop 元数据与 `IncompleteStreamError`、思考等级与显式的请求参数并入 MMSP-RFC-0003；最小化回传、思考的往返、`tool_call_id` 与不改变的历史消息并入 MMSP-RFC-0004；路由并入 MMSP-RFC-0005；凭据范围并入 MMSP-RFC-0006；有类型的拒绝与有类型的异常并入 MMSP-RFC-0007；中断并入 MMSP-RFC-0008；直白的转换、直观的实现代码与内容项的顺序并入 MMSP-RFC-0009。#298 按 0.5.6 的代码写下的规则也随之迁入：[#291](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/291) 的历史深拷贝，[#288](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/288) 与 [#290](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/290) 之后所有异常都有类型，[#289](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/289) 的配置页，以及 [#292](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/292) 的中断处理。#298 的 MMSP-RFC-0004、MMSP-RFC-0008、MMSP-RFC-0010 与 MMSP-RFC-0011 的文件在内容并入之后删除。
- 有三项内容第一次写成规范。MMSP-RFC-0009 §3 把 MMSP 定为所有转换的中间表示。MMSP-RFC-0004 §6 规定了完全相同的前缀：消息转换只读它所转换的消息和此前的消息，从不读之后的消息，所以过去的回合在每次调用中都以完全相同的形式发出，服务商的前缀缓存看到的是同一个前缀；`created_at` 不会发给任何服务商，`anthropic-official` 在 Bedrock 上放在最后一条用户消息上的缓存断点是唯一会移动的标记，它正是 Anthropic 为不断增长的对话给出的做法。MMSP-RFC-0010 规定了何时保存轨迹、轨迹包含什么，以及它写入的两个文件。
- [MMSP-RFC-0001](../../design/rfcs/MMSP-RFC-0001-rfc-process.zh.md) 改为编号的形式，并记下两次重编号，用一张表把 0.5.5 与 #298 的编号对应到现在承载其内容的规范。`design/README.md` 与 `design/README.zh.md` 的索引改为这十项规范。
- 两次重新表述都按代码改正了与之不符的说法。#298 按 0.5.6 的代码写下每条规则，并按代码改正了下面这些说法：embedding 来自不支持流式的端点；`google-genai` 在一个回合的第一个调用没有任何签名时，给它放上占位的思考签名；`ant-messages` 以 `{type: "tool", name}` 强制调用某个工具；Claude Fable 5 以最低的 effort 运行 `none`；Kimi K3 原样接受 `none`（[#294](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/294)）；网关的加密推理块记录为 `encrypted_content`、`format` 与 `reasoning_id`（[#287](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/287)）；没有拿到任何密钥的客户端也会抛出 `ApiKeyRequiredError`（[#288](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/288)）；中止错误是 MMSP 在 `integration/` 之外唯一抛出的内置错误；调用方在两次读取之间忙于别的事时中止 Python 的 `mmsp` 客户端，它在调用方下一次读取时关闭请求；早先版本在内容项内部记录、读取到 0.6.0 为止的形状，是以 bytes 保存的思考签名、不带通道的推理内容项和 0.5.5 的网关推理块，而等于函数名的工具调用 id 仍由 `google-genai` 记录。它的 `Enforced by` 一节（现为 Conformance）只写文件，不写私有类。随后这十项规范又逐句对照代码检查了一遍，#298 的下面这些说法得到改正：原说每个错误类仍是它所取代的内置错误，改为在 Python 中是 `ValueError`、在 TypeScript 中是 `Error`；无法获取的图片从 `InvalidMessageError` 的情形中删去，因为只有 TypeScript 在那里抛出它；没有密钥时抛出 `ApiKeyRequiredError` 的要求，从端点需要密钥的所有客户端收窄为基于 OpenAI SDK 的其他厂商官方客户端；`ProviderStreamError` 从服务商在流中报告的任何错误收窄为 Interactions API 的 `error` 事件，这个事件它的 SDK 不会抛出，SDK 自己的异常则原样传出；`EmptyResponseError` 加上了根本没有内容项的响应，`StreamProtocolError` 加上了第一个片段缺少名字或调用 id 的工具调用；原说 `_streaming_response_internal` 是对线上事件的一个简单循环，改为允许它补上需要配置与消息一起才能确定的请求内容，并根据同一条流中较早的事件修正一个事件；原说旧格式转换返回副本，改为已是当前格式的消息作为同一个对象返回，只复制需要转换的消息；Chat Completions 回传改为只在内容项没有指明字段时，才把思考同时放进两个推理字段；原说 `mmsp` 客户端的信号在两个包中都在两个事件之间结束它的流，改为在两个事件之间，TypeScript 中立即结束，Python 中在调用方下一次读取时结束。
- `site/astro.config.mjs` 把 0.5.5 与 #298 的每个 RFC 地址（`/docs/` 与 `/rfcs/` 下，两种语言）一次跳转到现在承载其内容的规范，`site/src/shared/docs.ts` 的 `docSummary` 改从 RFC 页面的 Abstract 读取 meta description。`AGENTS.md`、`mmsp-dev` skill、`README.md` 以及网站的 RFC 索引与设计页都把 RFC 称为规范；`AGENTS.md` 与 skill 加入了关于历史消息（MMSP-RFC-0004）与中断请求（MMSP-RFC-0008）的规则，并按新编号引用每项规范。0.5.5 各条目中的 RFC 链接改指现在承载其内容的规范，编号有变的加注「现为 MMSP-RFC-NNNN」。
