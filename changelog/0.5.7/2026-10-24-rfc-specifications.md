# The RFCs restated as ten specifications with noun titles

- **Date:** 2026-10-24
- **Type:** process
- **Scope:** `design`, `site`, `skills`, `docs`
- **PR:** [#298](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/298), [#301](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/301)

[中文版](2026-10-24-rfc-specifications.zh.md)

## What changed

- The RFCs became ten documents titled by nouns, as IETF RFCs are, in the order of the owner's Chinese titles, which are the H1s of the Chinese twins: MMSP-RFC-0001 The RFC Process (RFC 流程), MMSP-RFC-0002 Message Protocol (消息协议), MMSP-RFC-0003 Message Requests (消息请求), MMSP-RFC-0004 Message Fidelity (消息保真), MMSP-RFC-0005 Client Routing (客户端路由), MMSP-RFC-0006 Upstream Credentials (服务上游密钥), MMSP-RFC-0007 Error Types (异常类型), MMSP-RFC-0008 Request Interruption (请求中断), MMSP-RFC-0009 Protocol Conversion (协议转换), MMSP-RFC-0010 Trace Recording (轨迹记录).
- Every RFC took the form of `design/0000-template.md`: an Abstract, then numbered sections from Introduction and Conventions and Terminology to the body sections and, in a spec RFC, Conformance, renamed from Enforced by. Normative sentences use the BCP 14 key words MUST, MUST NOT, SHOULD, SHOULD NOT and MAY, which the Chinese twins write 必须, 不得, 应当, 不应 and 可以. The kind `rule` became `spec`, and the `[summary]: #summary` anchor lines were dropped.
- The content of the RFCs of 0.5.5 and of the twelve of #298 moved by topic: one protocol, two packages and lean messages into MMSP-RFC-0002; the stream grammar, the stop metadata and `IncompleteStreamError`, thinking levels and explicit request parameters into MMSP-RFC-0003; minimal replay, the thinking round trip, `tool_call_id` and the unchanging history into MMSP-RFC-0004; routing into MMSP-RFC-0005; the credential scope into MMSP-RFC-0006; typed rejection and typed errors into MMSP-RFC-0007; interruption into MMSP-RFC-0008; direct conversion, direct implementation and the order of content items into MMSP-RFC-0009. The rules #298 had written from the code of 0.5.6 went with them: the history copies of [#291](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/291), every error typed after [#288](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/288) and [#290](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/290), the configuration page of [#289](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/289) and the interruption of [#292](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/292). The files of #298's MMSP-RFC-0004, MMSP-RFC-0008, MMSP-RFC-0010 and MMSP-RFC-0011 were removed once their content was merged.
- Three things were specified for the first time. MMSP-RFC-0009 §3 made MMSP the intermediate representation of every conversion. MMSP-RFC-0004 §6 specified the identical prefix: a message transform reads the message it converts and the messages before it, never a later one, so a past turn goes out in the same wire form on every call and a provider's prefix cache sees the same prefix; `created_at` reaches no provider, and the cache breakpoint that `anthropic-official` places on the last user message on Bedrock, the one marker that moves, follows the pattern Anthropic documents for a growing conversation. MMSP-RFC-0010 specified when a trace is saved, what it contains and the two files it is written to.
- [MMSP-RFC-0001](../../design/rfcs/MMSP-RFC-0001-rfc-process.md) took the numbered form and recorded both renumberings, with one table from the numbers of 0.5.5 and of #298 to the specification that holds each one's content. `design/README.md` and `design/README.zh.md` indexed the ten specifications.
- Both restatements corrected what the code contradicted. #298 wrote every rule from the code at 0.5.6 and corrected these statements to it: embeddings come from an endpoint that does not stream; `google-genai` puts the placeholder thought signature on a turn's first call when nothing signed it; `ant-messages` forces a tool as `{type: "tool", name}`; Claude Fable 5 runs `none` at the lowest effort; Kimi K3 takes `none` as it is ([#294](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/294)); a gateway's encrypted reasoning block is recorded as `encrypted_content`, `format` and `reasoning_id` ([#287](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/287)); `ApiKeyRequiredError` is also raised for a client given no key at all ([#288](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/288)); the abort error is the one built-in error MMSP raises outside `integration/`; the Python `mmsp` client, aborted while its caller is busy between reads, closes its request at the caller's next read; the in-item shapes of earlier releases read until 0.6.0 are a thought signature as bytes, a reasoning item without its channel and the 0.5.5 gateway reasoning block, while a tool call id equal to the function name is still recorded by `google-genai`. Its `Enforced by` sections, now Conformance, named files, not private classes. The ten specifications were then checked against the code sentence by sentence, and these statements of #298 were corrected: each error class, said to be the built-in it replaced, became a `ValueError` in Python and an `Error` in TypeScript; an image that cannot be fetched was removed from the `InvalidMessageError` cases, since only TypeScript raises it there; `ApiKeyRequiredError` for a client given no key was narrowed from every client whose endpoint needs a key to the official clients of other vendors built on the OpenAI SDK; `ProviderStreamError` was narrowed from any error a provider reports inside a stream to the Interactions API's `error` event, which its SDKs do not raise, while an SDK's own exception propagates as it is; `EmptyResponseError` gained the response with no item at all, and `StreamProtocolError` the tool call whose first fragment lacks its name or call id; `_streaming_response_internal`, called a plain loop over the wire, was allowed to complete the request with what needs the config and the messages together and to correct an event from an earlier one of its stream; legacy conversion, said to return copies, was corrected to return a current message as the same object and copy only a message it converts; a Chat Completions replay was corrected to send thinking through both reasoning fields only when its item names no field; and the `mmsp` client's signal, said to end its stream between events in both packages, was corrected to end it there at once in TypeScript and at the caller's next read in Python.
- `site/astro.config.mjs` redirected every RFC URL of 0.5.5 and of #298, under `/docs/` and `/rfcs/` in both languages, in one hop to the specification that holds its content, and `docSummary` in `site/src/shared/docs.ts` read an RFC page's meta description from its Abstract. `AGENTS.md`, the `mmsp-dev` skill, `README.md` and the site's RFC index and design page called the RFCs specifications; `AGENTS.md` and the skill gained the rules on history (MMSP-RFC-0004) and interruption (MMSP-RFC-0008) and cited every specification by its new number. The RFC links of the 0.5.5 entries were pointed at the specification that holds their content, with "now MMSP-RFC-NNNN" where the number changed.
