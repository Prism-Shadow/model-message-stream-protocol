## What changed

- Implemented the web tool parts of [MMSP-RFC-0002](../../design/rfcs/MMSP-RFC-0002-message-protocol.md), [MMSP-RFC-0003](../../design/rfcs/MMSP-RFC-0003-message-requests.md), [MMSP-RFC-0005](../../design/rfcs/MMSP-RFC-0005-client-routing.md) and [MMSP-RFC-0006](../../design/rfcs/MMSP-RFC-0006-upstream-credentials.md), as amended in [#308](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/308).
- Two clients, in Python and TypeScript: `deepseek-webtool` (`DeepSeekWebtoolClient`) for DeepSeek's Search and Fetch, `POST /v1/tools/search` and `/v1/tools/fetch` under `https://api.deepseek.com` or TokenDance's `https://tokendance.space/gateway/deepseek`; and `jina-webtool` (`JinaWebtoolClient`) for Jina's Search, `POST https://s.jina.ai/search`, and Reader, `POST https://r.jina.ai/`. Both send their requests through the OpenAI SDK's `post`. The models are `deepseek-search`, `deepseek-fetch`, `jina-search` and `jina-fetch`; the `-search` or `-fetch` in the id selects the tool.
- Routing: `deepseek-official` served `deepseek-search` and `deepseek-fetch` through `deepseek-webtool`, named or deduced. The family `jina-` named `jina-webtool`, listed among the official client types.
- Items: `webtool.delta` and `webtool.done`, whose `webdata` lists `{title, content, url}`. `StreamItems` closed each answer as one item, a search that found nothing included.
- `UniConfig.webtool_config.count`: how many results a search returns.
- Each message was one request, its text the query or the URL. The stop event carried `finish_reason: "stop"` and `prompt_tokens`: 1 per request on DeepSeek, which bills by the request, and Jina's `meta.usage.tokens`, summed over the requests.
- `list_models` on both clients raised `UnsupportedOperationError`; a non-text item raised `UnsupportedContentError`; `fast_mode` raised `UnsupportedParameterError`; a model id without `-search` or `-fetch` raised `UnsupportedOperationError` when the client was built.
- Credentials: `ClientCredentials` gained `other_base_urls` (`otherBaseUrls`), the client's other default endpoints. `jina-webtool` reads `JINA_API_KEY` for `https://r.jina.ai` and `https://s.jina.ai`, and calls the one that serves its model when given no base URL. `deepseek-webtool` shares `DEEPSEEK_API_KEY` and `DEEPSEEK_BASE_URL` with `deepseek-official`.
- The tracer and the playground showed a web tool item as its pages: title, address and the first lines of the content. The playground and server pages described both client types.
- `.github/ci/models.json` gained the `deepseek-webtool` group (`deepseek-search`, `deepseek-fetch`, and `deepseek-search` on TokenDance as a slow case) and the `jina-webtool` group (`jina-search`, `jina-fetch`); `pytest.yml` and `jest.yml` passed `JINA_API_KEY`. The shared e2e tests gained `support_webtool` and the web search and fetch cases.
- Docs: the configuration page gained `webtool_config` and both clients' rows; the messages, streaming, models, client and errors pages, the README, the package READMEs, `AGENTS.md`, the dev skill and both `skills/` packages named the new clients, items and key. Added the `llmsdk_docs/deepseek_webtool/` and `llmsdk_docs/jina_webtool/` snapshots.

## Configuration behavior

| `UniConfig` | `deepseek-webtool` | `jina-webtool` |
| --- | --- | --- |
| `webtool_config.count` on a search | `count`, 1 to 50 | `num`, 0 to 20 |
| `webtool_config.count` on a fetch | ignored | ignored |
| `fast_mode: true` | `UnsupportedParameterError` | `UnsupportedParameterError` |
| Every other key | ignored | ignored |

## Wire mapping

| | `deepseek-webtool` | `jina-webtool` |
| --- | --- | --- |
| Search request | `{"query": <text>, "count"?}` | `{"q": <text>, "num"?}` with `X-Respond-With: no-content` |
| Search result's `content` | `summary` | `description` |
| Fetch request | `{"url": <text>}` | `{"url": <text>}` |
| Fetch page's `url` | the URL sent | `data.url` |
| `prompt_tokens` | 1 per request | `meta.usage.tokens` |
