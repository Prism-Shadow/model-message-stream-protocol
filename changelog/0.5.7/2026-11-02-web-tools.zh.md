# 网页搜索与网页抓取

- **Date:** 2026-11-02
- **Type:** feature
- **Scope:** `deepseek_webtool`, `jina_webtool`, `types`, `credentials`, `integration`
- **PR:** [#310](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/310)

[English](2026-11-02-web-tools.md)

## 变更内容

- 实现了 [#308](https://github.com/Prism-Shadow/model-message-stream-protocol/pull/308) 在 [MMSP-RFC-0002](../../design/rfcs/MMSP-RFC-0002-message-protocol.zh.md)、[MMSP-RFC-0003](../../design/rfcs/MMSP-RFC-0003-message-requests.zh.md)、[MMSP-RFC-0005](../../design/rfcs/MMSP-RFC-0005-client-routing.zh.md) 与 [MMSP-RFC-0006](../../design/rfcs/MMSP-RFC-0006-upstream-credentials.zh.md) 中写入的网页工具部分。
- 新增两个客户端，Python 和 TypeScript 同步：`deepseek-webtool`（`DeepSeekWebtoolClient`）对接 DeepSeek 的 Search 和 Fetch，即 `https://api.deepseek.com` 或 TokenDance 的 `https://tokendance.space/gateway/deepseek` 下的 `POST /v1/tools/search` 和 `/v1/tools/fetch`；`jina-webtool`（`JinaWebtoolClient`）对接 Jina 的 Search（`POST https://s.jina.ai/search`）和 Reader（`POST https://r.jina.ai/`）。两者都通过 OpenAI SDK 的 `post` 发请求。模型为 `deepseek-search`、`deepseek-fetch`、`jina-search` 和 `jina-fetch`，由 ID 里的 `-search` 或 `-fetch` 选择工具。
- 路由：`deepseek-official` 通过 `deepseek-webtool` 服务 `deepseek-search` 和 `deepseek-fetch`，显式指定和按 ID 推断都是如此。新增模型家族 `jina-`，对应 `jina-webtool`，后者列入官方客户端类型。
- 内容项：新增 `webtool.delta` 和 `webtool.done`，其 `webdata` 是 `{title, content, url}` 的列表。`StreamItems` 把每次回答收为一个内容项，搜索无结果时也是如此。
- `UniConfig.webtool_config.count`：一次搜索返回的结果条数。
- 每条消息是一次请求，消息文字即查询词或 URL。stop 事件带 `finish_reason: "stop"` 和 `prompt_tokens`：DeepSeek 按次计费，每次请求记 1；Jina 取 `meta.usage.tokens`；多次请求相加。
- 两个客户端的 `list_models` 抛出 `UnsupportedOperationError`；非文本内容项抛出 `UnsupportedContentError`；`fast_mode` 抛出 `UnsupportedParameterError`；ID 里既没有 `-search` 也没有 `-fetch` 时，构造客户端即抛出 `UnsupportedOperationError`。
- 凭据：`ClientCredentials` 新增 `other_base_urls`（`otherBaseUrls`），即客户端的其他默认端点。`jina-webtool` 对 `https://r.jina.ai` 和 `https://s.jina.ai` 都读取 `JINA_API_KEY`，未传 base URL 时调用服务其模型的那个端点。`deepseek-webtool` 与 `deepseek-official` 共用 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_BASE_URL`。
- Tracer 和 playground 把网页工具内容项显示为页面列表：标题、地址和内容的前几行。playground 和 server 页面为两个客户端类型加上了说明。
- `.github/ci/models.json` 新增 `deepseek-webtool` 组（`deepseek-search`、`deepseek-fetch`，以及 TokenDance 上作为慢用例的 `deepseek-search`）和 `jina-webtool` 组（`jina-search`、`jina-fetch`）；`pytest.yml` 和 `jest.yml` 传入 `JINA_API_KEY`。共享 e2e 测试新增 `support_webtool` 能力标记和网页搜索、网页抓取用例。
- 文档：配置页新增 `webtool_config` 和两个客户端的行；messages、streaming、models、client、errors 各页，README，两个包的 README，`AGENTS.md`，开发 skill 和 `skills/` 下的两个包都写入了新客户端、内容项和密钥。新增 `llmsdk_docs/deepseek_webtool/` 和 `llmsdk_docs/jina_webtool/` 文档快照。

## 配置行为

| `UniConfig` | `deepseek-webtool` | `jina-webtool` |
| --- | --- | --- |
| 搜索时的 `webtool_config.count` | `count`，取 1 到 50 | `num`，取 0 到 20 |
| 抓取时的 `webtool_config.count` | 忽略 | 忽略 |
| `fast_mode: true` | `UnsupportedParameterError` | `UnsupportedParameterError` |
| 其他所有键 | 忽略 | 忽略 |

## 线上映射

| | `deepseek-webtool` | `jina-webtool` |
| --- | --- | --- |
| 搜索请求 | `{"query": <文字>, "count"?}` | `{"q": <文字>, "num"?}`，带 `X-Respond-With: no-content` |
| 搜索结果的 `content` | `summary` | `description` |
| 抓取请求 | `{"url": <文字>}` | `{"url": <文字>}` |
| 抓取页面的 `url` | 发送的 URL | `data.url` |
| `prompt_tokens` | 每次请求记 1 | `meta.usage.tokens` |
